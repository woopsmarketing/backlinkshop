# STEP 0 — 템플릿 계약서 (Template Contract)

> site-factory-next · template-first MVP의 **인터페이스 명세 + 복제 절차**
> 이 문서는 "인터페이스에만 구체적이고, 각 템플릿의 디자인에는 침묵한다."
> 즉 슬롯 이름·타입·토큰 규칙은 못박되, 레이아웃은 템플릿마다 자유.
> Claude Code(실행)는 이 계약서를 기준으로 템플릿을 복제·등록한다.

---

## 0. 한 줄 원칙

**레이아웃은 박제한다. 내용만 주입한다.**
아무리 복잡하게 디자인된 구조라도, 배치를 한 번 고정하면 그 안은 "빈칸 채우기"가 된다.

---

## 1. 세 개의 층 (무엇이 어디에 사는가)

| 층        | 무엇                                          | 어디에                                      | 변하나?          |
| --------- | --------------------------------------------- | ------------------------------------------- | ---------------- |
| **FIXED** | 레이아웃·배치·크기·위치·패딩·마진·호버·반응형 | 컴포넌트 코드 (.tsx)                        | ❌ 템플릿이 박제 |
| **TOKEN** | 색·폰트·모서리 반경                           | CSS 변수 `--c-*` / `--f-*` / `--r-*` (테마) | ✅ 테마로 교체   |
| **SLOT**  | 글자·이미지·리스트 내용                       | props (page-data로 주입)                    | ✅ 고객마다 교체 |

판단 기준:

- 간격(패딩/마진)은 **레이아웃**이므로 FIXED (코드). 테마가 못 건드린다.
- 버튼의 위치·호버·반응형은 FIXED (코드).
- 버튼의 색·반경은 TOKEN (테마).
- 버튼의 글자는 SLOT.

---

## 2. 슬롯 타입 (4종)

| 타입               | 설명                            | 예시                                     |
| ------------------ | ------------------------------- | ---------------------------------------- |
| **scalar**         | 칸 하나 = 값 하나               | `headline`, `ctaPrimaryLabel`            |
| **image**          | 이미지 URL 1개                  | `heroImage`, `card.media`                |
| **color**          | 색 1개 (보통 테마가 담당)       | accent 등                                |
| **list (min~max)** | 같은 모양이 N개 반복, 개수 가변 | `navLinks`, `features`, `logos`, `stats` |

리스트 슬롯 규칙:

- 구현은 `.map()` 한 줄. 개수 가변은 **쉬운 일**이다.
- 단, **min~max를 정한다** (레이아웃이 안 깨지도록). 예: `navLinks 3~6`, `features 3~6`, `logos 3~8`, `stats 2~4`.
- ⚠️ "항목마다 *구조*가 다른" 가변(1번은 grid, 2번은 carousel)은 리스트 슬롯이 아니다 →
  그건 **레이아웃을 박제**해서 흡수한다(벤토처럼). 런타임에 배치를 새로 짜지 않는다.

---

## 3. 슬롯 이름 사전 (컨벤션)

모든 템플릿이 **같은 이름**을 쓴다. 의미가 같으면 재사용, 진짜 새로운 것만 추가(분열 금지).
이름이 제각각이면 content-builder가 어디에 꽂을지 몰라 자동화가 깨진다.

**공통 (scalar)**
`logoText` · `loginLabel` · `navCtaLabel` · `heroEyebrow` · `headline`(1~2줄 배열) ·
`heroSubhead` · `ctaPrimaryLabel` · `ctaSecondaryLabel` · `sectionTitle` ·
`footerTagline` · `copyright`

**공통 (image)**
`heroImage`(또는 `heroMedia`: 이미지/영상) · `card.media`

**공통 (list)**
`navLinks[]` {label} · `logos[]` {name|image} ·
`features[]` {icon, title, body, media?} · `stats[]` {value, label} ·
`footerCols[]` {head, links[]}

> 새 섹션(pricing 등)을 가져오면 여기에 이름을 **추가**한다.
> 예: `plans[]` {name, price, period, featureList[], ctaLabel}

---

## 4. 토큰 이름 규칙 (테마)

- 색: `--c-page` `--c-surface` `--c-text` `--c-text-muted` `--c-accent` `--c-accent-text` `--c-border` `--c-grad-1..n` `--c-footer-bg` `--c-footer-text`
- 폰트: `--f-heading` `--f-body` `--f-heading-weight`
- 반경: `--r-button` `--r-card`

원칙: **부품은 토큰을 "참조"만 한다.** 테마 = 이 변수에 값을 꽂는 자리.
복제할 때 원본의 색·폰트·반경을 추출해 **"그 템플릿의 기본 테마" 1개를 함께 만든다**(원본 룩 보존).
빼두는 건 공짜 옵션 — 안 바꾸면 원본 그대로, 바꾸면 갈아끼움.

---

## 5. 복제 절차 (Claude Code가 따르는 단계 = 나중 하네스의 설계도)

1. **레퍼런스 수집** — URL 있으면 HTML/CSS 크롤 우선(호버·동작 정보 포함), 없으면 스크린샷.
2. **충실 복제** — Next + React + Tailwind로 깨끗하게 재구축.
   - **기본값 = 충실 복제.** 단순화는 사람이 "단순하게"라고 *명시*할 때만.
3. **토큰화** — 박혀온 색/폰트/반경을 `--c-*`/`--f-*`/`--r-*`로 추출 → 기본 테마 생성.
   - `bg-blue-600` 같은 literal이 하나도 안 남게 (= placeholder leak 방지).
4. **슬롯화** — 글자·이미지·리스트를 props로 분리, §3 사전 이름 사용.
   - 디자인된 구조는 레이아웃을 박제하고 내용만 슬롯으로.
5. **반응형** — 모바일 최적화 필수(데스크탑 전용 금지). 좁은 화면은 스택/햄버거.
6. **검수** — 슬롯 경계 토글로 빈칸 확인, 테마/콘텐츠 스왑해도 깨지지 않는지 눈검수.
7. **등록** — 갤러리에 named 템플릿으로.

---

## 6. 변하지 않는 규칙

- **충실 복제가 기본.** 레퍼런스를 주면 잘 만든다. 단순화는 지시가 있을 때만.
- **다양성 = 템플릿 개수.** "한 템플릿에 옵션을 늘리기"가 아니라 "템플릿을 더 만들기"로 다양성 확보. 벤토·그리드·풀블리드 다 갤러리에 공존.
- **업종이 디자인을 가르지 않는다.** 어떤 레이아웃이든 카페·의원·SaaS 누구나 고를 수 있다. 안의 내용만 자기 것으로.
- **이미지 슬롯 fallback:** 고객 미제공 시 Unsplash 또는 gpt-image로 채움. 슬롯별 권장 크기 미리 정의.
- **호버 등 동작:** HTML 있으면 충실 복제, 스크린샷뿐이면 표준 호버(예: 살짝 어두워짐)를 기본값으로.

---

## 7. 하지 않는 것 (오버엔지니어링 / 깨졌던 것)

- ❌ **런타임 자동 조립(selector).** 템플릿은 사람/고객이 갤러리에서 고른다. selector가 "이 사업에 이 컴포넌트?"를 판단하지 않는다.
- ❌ **컴포넌트마다 하네스 N개.** 페이지(또는 섹션)를 받아 초안을 뱉는 하네스는 **1개**. 입력만 여럿.
- ❌ **자동 템플릿 선택기.** 갤러리 수동 선택이 MVP.
- ❌ **항목마다 구조가 다른 런타임 가변.** 디자인은 박제로 흡수.
- ❌ **계약서가 각 템플릿 레이아웃까지 규정하기.** 계약서는 인터페이스만. 레이아웃은 자유.
- ❌ **미래 기능을 지금 계약서에 상세 설계.** 블로그·예약·결제 등은 §10 로드맵에 한 줄만. 상세는 그때.

---

## 8. IP 라인 (베끼는 선)

- ✅ 가져온다: 구조·레이아웃 패턴, 색·타이포 _분위기_.
- ❌ 안 가져온다: 원본의 고유 사진/일러스트/영상 자산, 원본 마케팅 카피 그대로, "딱 봐도 걔네 사이트"인 픽셀 단위 복제.
- 카피·이미지는 슬롯이라 고객 것으로 바뀌므로 핵심 위험은 자동 소거. 팔레트·폰트는 테마로 교체하면 자연히 안전.

---

## 9. (참고용 · 지금은 몰라도 됨) 기존 시스템 / 배포 기술 메모

> 이 섹션은 *옛날 코드*를 어떻게 정리할지에 대한 메모다.
> **MVP 디자인 작업에는 영향 없으니, 이해 안 되면 넘어가도 된다.** CLI에서 정리할 때 참고.

- **IR(옛날 페이지 저장 방식)** 은 template-first에선 거의 안 쓴다. 페이지가 그냥 React라서.
- 무거운 조립층(adapter/assembler/카탈로그)은 **은퇴**. 얇은 `page-data`(주소 + 슬롯값 + (나중)seo)만 유지.
- 테마는 이 옛 방식과 무관하게 CSS로 따로 돈다(깨끗하게 분리됨 = 좋음).
- 배포: 방문자에겐 **정적 HTML**(미리 구운 파일)을 빠르게 서빙. 동적이 필요한 순간만 서버 함수.

## 10. 로드맵 (나중 — 지금은 한 줄만, 상세 설계는 그때)

- **v1 (지금):** 이쁜 랜딩 템플릿. 100% 정적. SEO 없음.
- **v1.5:** SEO·구조화 마크업 — json-ld, robots.txt, sitemap, llm.txt, 메타. (page-data에 `seo` 블록 추가)
- **v2 (MVP 직후 시급):** **블로그** — 글 페이지 템플릿 + 목록 페이지. **정적**으로(글 데이터 → 빌드 시 굽기). 랜딩과 같은 슬롯 원리.
- **v2+:** 동적 기능(예약 접수·저장, 로그인, 결제). Cloudflare Workers/D1 등으로 — **전용 서버 불필요**.

---

_이 계약서는 살아있는 문서다. 템플릿을 만들며 사전·규칙이 늘어나면 여기에 추가한다(추가만, 분열 금지)._
