# LP /seo 결과 페이지 — VebAPI 확장 전략 논의

**날짜**: 2026-04-25
**주제**: `/lp/seo` 폼 제출 → `/analyze/[domain]` 결과 페이지에 VebAPI 데이터를 확대 적용하는 방안과 API 사용량 증가 추정

---

## 배경

- 기존 결과 페이지 섹션 순서: **KPI → 경쟁사 비교 → 격차 → 온페이지 → AI 분석**
- 현재 사용 중인 데이터 소스:
  - RapidAPI `domain-metrics-check` (DA/DR/TF/CF, 백링크, 트래픽, 키워드)
  - VebAPI `/backlinkdata` (백링크)
  - Serper (SERP)
  - 자체 크롤러 (온페이지)
- `PROMPT/general.md`에 VebAPI의 풍부한 엔드포인트 목록이 있으나 **대부분 미사용 상태**

---

## 핵심 전략 — "데이터 양이 아니라 구매 전환 트리거"

랜딩 목적은 텔레그램 상담 전환이므로, 데이터는 다음 3단 감정을 유발해야 함:

1. **인식** — "내 상태 이 정도" (KPI)
2. **고통** — "경쟁사 대비 격차 + 독성 링크 + AI 미노출" (격차/리스크)
3. **해결 욕구** — "상담 받자" (CTA)

백링크 판매 사업이므로 "링크로 해결 가능한 문제"를 부각시키는 API를 최우선으로 붙여야 함.

## 결과 페이지 섹션 재설계

```
0. 헤더 (기존 + 스크린샷 + 도메인 나이 뱃지)
1. 🆕 타겟 키워드 현재 순위 배너
2. KPI 카드 (+ 신규백링크/랭킹키워드 수 카드 추가)
3. 경쟁사 비교 테이블 (+ 신규백링크 속도 칼럼)
4. 격차 카드 (+ AI 가시성 격차 항목)
5. 🆕 위험 신호 — 독성 백링크 + AI 봇 차단 여부  ← 상담 CTA 삽입
6. 온페이지 (기존 크롤러 + AI Visibility 병합)
7. 🆕 키워드 확장 기회
8. AI 상세 분석 (기존)
9. 최종 CTA
```

**핵심**: 5번(위험)과 7번(기회) 사이에 상담 CTA 추가 → 전환율 피크 지점.

## API 사용량 추정 (콜드 분석 1건, 경쟁사 5개 기준)

### 현재 베이스라인

| 소스                    | 호출 수 | 캐시        |
| ----------------------- | ------- | ----------- |
| Serper SERP             | 1       | 키워드 14일 |
| RapidAPI domain-metrics | 6       | 도메인 30일 |
| VebAPI `/backlinkdata`  | 6       | 도메인 30일 |

**현 VebAPI 콜드: 6회/분석**

### 시나리오별 VebAPI 호출 수

| 시나리오                    | VebAPI/분석 | 현재 대비   |
| --------------------------- | ----------- | ----------- |
| 현재                        | 6           | 1.0x        |
| Phase 1 절약                | 9           | 1.5x        |
| Phase 1 풀                  | 15          | 2.5x        |
| Phase 1+2 절약              | 13          | 2.2x        |
| **Phase 1+2+3 절약 ← 추천** | **16**      | **2.7x**    |
| Phase 1+2+3 풀              | 32          | 5.3x (과다) |

### 월간 실사용 추정 (일 30건, 콜드 40% 가정)

| 시나리오               | 월 VebAPI 호출 |
| ---------------------- | -------------- |
| 현재                   | ~2,160         |
| **추천 (절약형 올인)** | **~5,760**     |
| 풀 올인                | ~11,520        |

→ 추천안은 약 **월 +3,600회 증가**, VebAPI 요금제 한 단계 내에서 흡수 가능한 범위.

RapidAPI, Serper는 변동 없음 (새 기능 전부 VebAPI).

## CTO 구현 권고

1. **절약형 올인(2.7x) 채택** — 호출당 부가가치 최상
2. **`/single-keyword` 제외** — `/keywordresearch` 응답에 볼륨/competition 포함되는 경우가 많음, 10배 호출량 대비 실익 낮음
3. **경쟁사 확장은 `/new-backlinks` 1개에만 적용** — 도메인 나이, 참조 도메인 품질을 경쟁사까지 돌리면 +10 즉시 추가
4. **크레딧 가드 필수** — `/api/lp/request` 진입 시 `/vebapi-credits`로 잔량 체크 → 임계치 이하면 Phase 2·3 섹션 skip (graceful degrade). 일일 cron으로 잔량 모니터링
5. **캐시 키 분리**:
   - 도메인 30일 (DA/DR, 독성링크, 도메인 나이, AI 크롤러, 스크린샷 등)
   - 키워드 7일 (AI Overview, Perplexity — 변동 빠름)
   - 스크린샷 90일
6. **병렬 + 부분 실패 허용** — 새 API는 `Promise.allSettled`로 묶고 섹션별 DB 필드 분리 → 하나 실패해도 나머지 노출
7. **점진적 렌더** — 기존 `status` 폴링에 섹션별 완료 플래그(`serp_done`, `poor_backlinks_done`…) 추가 → 프론트에서 섹션별 skeleton → 완료 순 렌더
