## 0-A. 이번 업데이트 핵심 변경 사항 [필수 요약]

현재 LP 구조의 **이메일 지연 발송(10분 대기)** 이 광고 유입 대비 전환율을 떨어뜨리는 주 원인으로 판단됨. 다음 UX 개편을 전제로 광고 셋팅을 진행:

1. **폼 제출 → 즉시 결과 페이지로 이동** (도메인 기반 URL 인라인 렌더링)
   - 예: `seoworld.co.kr` 제출 시 → `https://www.backlinkshop.co.kr/analyze/seoworld.co.kr`
   - 동일 세션에서 결과 + 텔레그램 문의 CTA 노출
2. **이메일은 계속 수집** (리포트 백업 발송 + 장기 리텐션 마케팅용 리스트)
3. **대표 전환 = 텔레그램 문의 클릭**, **보조 전환 = 폼 제출**
4. 월 광고 예산: **500,000 ~ 600,000원** (기존 50만원 → 최대 60만원)

→ UX 개편이 유효하면 사이트 코드 변경까지 진행할 계획. 상세 논의는 본 문서 하단 § A 참고.

## 2. 자세한 사업 설명 [필수]

```
백링크샵은 "구글 상위노출의 숨은 공식 = 백링크 + 내부 SEO" 라는 전제에서 출발한 국내 최대 규모의 SEO·백링크 원스톱 커머스 플랫폼입니다.
크레딧 기반으로 운영되며, 가입 즉시 20만 크레딧(약 20만원 상당)을 무료로 지급해 카드 등록 없이 전 기능을 체험할 수 있습니다.

제공 서비스:
(1) DA 30 이상 검증된 화이트햇 도메인에서만 발급되는 백링크 상품 구매
(2) 도메인 URL 하나만 넣으면 50개 이상 항목을 자동 분석하는 SEO 진단 리포트 (현재 LP의 메인 오퍼)
(3) 진단 결과를 바탕으로 부족한 영역만 추가 구매해 보강하는 내부 SEO 개선 상품
(4) 주문·진행 현황·성과 리포트를 한 대시보드에서 관리하는 자체 운영 콘솔

주 타깃:
- 쇼핑몰·이커머스 운영자 (카페24·쇼피파이·자체몰·네이버 스마트스토어 탈피형)
- 블로그·콘텐츠 사이트 운영자 (티스토리·워드프레스 기반 애드센스·제휴 수익형)
- 랜딩페이지 기반 단일 퍼널 비즈니스 운영자 (강의·상담·리드 수집형)
- 웹 플랫폼·SaaS 운영자 (B2B·B2C 공통)
- SEO 대행사·프리랜서 마케터 (B2B, 에이전시 도매)

공통 니즈: "구글 검색 상위노출" 을 원하지만, 뭘 해야 할지 우선순위를 모르는 사람들.
```

## 3. 타깃 고객 (ICP) [필수]

### 3-1. 누가 사나요? [필수]

```
페르소나 A — "구글 노출 안 되는 쇼핑몰·이커머스 운영자" (결제 비중 35%)
  30~40대 자영업자/1인 쇼핑몰 대표. 카페24·쇼피파이·자체몰·네이버 스마트스토어에서 구글 검색 트래픽 확장을 원함.
  네이버 쇼핑광고 CPC 인상으로 대체 채널 필요. SEO 직접 공부할 시간 없음. 월 매출 1천만~수억원.

페르소나 B — "블로그·콘텐츠 사이트 운영자" (결제 비중 25%)
  20대 후반~30대. 티스토리·워드프레스로 애드센스·제휴 수익. "백링크" 용어는 알고, 블랙햇 공포 존재.
  "안전한 공급처" 를 찾고 있음.

페르소나 C — "랜딩페이지·단일 퍼널 운영자" (결제 비중 15%)
  강의·상담·리드 수집형 사이트 운영자. 키워드 1~2개에 집중해야 하는 구조.
  SEO 로 저비용 리드 수집이 목표 — 유료 광고비 절감 니즈 강함.

페르소나 D — "웹 플랫폼·SaaS 운영자" (결제 비중 10%)
  B2B·B2C SaaS, 커뮤니티, 매칭 플랫폼 등. 도메인 권위도(DA) 와 기술 SEO 이슈가 복잡해 외부 진단 필수.

페르소나 E — "에이전시·프리랜서 마케터 (B2B)" (결제 비중 15%, 객단가 최고)
  30~40대 퍼포먼스·SEO 마케터, 대행사 기획자. 자체 클라이언트 용 안전한 백링크 공급처 + 객관 리포트 필요.
  B2B 도매 가격·대량 할인·월간 성과 리포트 민감.
```

### 3-2. 그들이 해결하고 싶은 문제 [필수]

```
- 네이버는 되는데 구글 검색에서는 내 사이트가 안 보인다 — "왜" 인지 모른다.
- SEO 에이전시 견적은 월 30~200만원인데 뭘 해줄지 불투명하고, 계약 전 검증 수단이 없다.
- "백링크" 가 중요한 건 아는데 블랙햇·PBN 품질 의심, 구글 패널티 공포, 가격 편차가 심해서 못 사고 있다.
- 경쟁사는 이미 구글 1페이지에 있는데 내가 뭘 해야 따라잡을지 우선순위를 모른다.
- 에이전시: 내 클라이언트에 쓸 안전한 백링크 공급원과 객관 리포트가 필요하다.
- 쇼핑몰·랜딩페이지: 네이버 파워링크 CPC 인상 → 구글로 대체 채널 찾고 있다.
```

### 3-3. 왜 지금 사나요? (구매 트리거) [권장]

```
- 네이버 광고비(파워링크·쇼핑검색) CPC 가 계속 올라 대체 채널로 구글 검토 중.
- 자체몰 리뉴얼 직후 / 신규 쇼핑몰·랜딩페이지 오픈 직후 트래픽이 안 붙을 때.
- 경쟁사가 구글 1페이지에 뜨는 걸 본 직후.
- SEO 에이전시 견적을 받았는데 금액이 부담돼 "내가 뭘 해야 할지만이라도" 알고 싶을 때.
- 에이전시·프리랜서: 새 클라이언트 온보딩 직후 초기 진단 자료 필요.
- 광고로 유입되는 고객은 "지금 당장" 해결하고 싶은 의도가 강함 — 10분 이메일 대기 구조는 이 의도를 놓침.
```

### 3-4. 구매 전에 망설이는 이유 (반박 포인트) [권장]

```
- "백링크 = 블랙햇 = 구글 패널티" 공포 → LP·결과페이지에서 "DA 30+ 검증, 화이트햇, 패널티 0건" 반복 해소.
- "무료 진단 받으면 영업 전화 쏟아지는 거 아니야?" → "카드 등록 불필요, 텔레그램 or 이메일 선택" 강조.
- "결과 안 나오면 돈 날리는 거잖아" → 20만 크레딧 무료 지급으로 "돈 쓰기 전 체험" 구조.
- "에이전시 계약보다 저렴해도 품질이 그만큼 낮지 않나?" → 리포트 샘플·누적 고객·원스톱 범위로 반박.
- "이메일로 받을 것 없이 지금 당장 보고 싶다" → 결과 페이지 인라인 렌더링으로 해결 (핵심 개선 포인트).
```

## A. UX 개편 논의 요약 (v1.1 추가)

### A-1. 왜 이 개편이 필요한가

```
현재 구조:
  광고 클릭 → LP → 폼 제출 → "이메일로 10분 뒤 발송" 안내 → 페이지 이탈 → (사용자 컨텍스트 소실) → 이메일 확인 비율 낮음 → 전환 저조

구조적 문제:
  1. 광고로 유입된 고객은 "지금 당장" 을 원함. 10분 대기 = 의도 휘발.
  2. 페이지 이탈 후 이메일 확인까지 평균 시간 > 의도 유지 시간.
  3. 이메일 도착 시점에는 CTA 클릭 의지가 이미 사라짐.
  4. 결제 전환을 위한 1:1 상담 진입 경로가 이메일 안에만 있음.
```

### A-2. 개편 후 구조

```
  광고 클릭 → LP → 폼 제출 → /analyze/{도메인} 즉시 이동 → 결과 렌더링 →
    세션 유지 중 텔레그램 CTA 다중 노출 → 고의도 상태에서 클릭 → 운영자 실시간 응답 →
      상담 → 결제

  + 이메일 백업 발송 (리텐션 자산 유지)
```

### A-3. 기대 효과 (가설)

| 지표                   | 현재               | 개편 후 기대                   | 근거                      |
| ---------------------- | ------------------ | ------------------------------ | ------------------------- |
| 폼 제출 후 CTA 클릭률  | 낮음 (이메일 의존) | 3~10배                         | 동일 세션 내 유지         |
| 텔레그램 문의율 / 방문 | 0 → 5~15%          | 신규 경로 개설                 | 즉시성 · 컨텍스트 유지    |
| 유료 결제 전환율       | 미상 (느린 파이프) | 2~5배                          | 1:1 상담 경유 객단가 상승 |
| 이메일 수집량          | 변동 없음          | 동일 유지                      | 폼 필수 필드 유지         |
| CPA (텔레그램 기준)    | —                  | 초기 30,000원 → 3주차 15,000원 | 학습 후 하향              |

### A-4. 구현 체크리스트

```
[필수]
□ /app/analyze/[domain]/page.tsx 신규 라우트
□ 폼 제출 서버 액션 → 도메인 검증(DNS 존재 + 유효 URL) → /analyze/{도메인} 302 리다이렉트
□ 분석 엔진 pre-compute 단계 (3초 내): SSL / meta / H1 / 기본 응답 속도
□ 나머지 항목은 페이지 진입 후 async 로딩 (Suspense + 스켈레톤)
□ 동일 도메인 재제출 시 캐시된 결과 즉시 재사용 (기존 `캐시 API 3개` 활용 가능 — 커밋 c817814·fe2e0f3 참조)
□ 결과 페이지 내 텔레그램 CTA 3개 이상 배치 (상단 · 개선 항목별 · 하단 스티키)
□ GA4 `telegram_click` 이벤트 + Google Ads 전환 가져오기
□ 결과 페이지 meta noindex,nofollow
□ 이메일 백업 발송 (기존 로직 재사용)

[방어]
□ Cloudflare Turnstile 캡차 (스팸 방지)
□ 동일 IP 분당 N회 제한 (rate limiting)

□ Google Ads 에 `telegram_click` = 주 전환 등록

□ 기존 `sign_up` 은 부 전환 관찰용
```

### A-5. 리스크

```
1. 결과 페이지 퀄리티 이슈
```
