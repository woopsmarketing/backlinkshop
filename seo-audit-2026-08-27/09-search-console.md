# Search Console 데이터 분석 — **데이터 필요**

**조사일: 2026-08-27**

---

## 9-1. 결론: 접근 권한 없음 → `데이터 필요`

프롬프트 지시("Search Console 접근이 없다면 이 부분은 `데이터 필요`로 명시하세요")에 따라 명시합니다.

**Google Search Console 접근 권한이 제공되지 않아 이 섹션의 모든 항목은 `데이터 필요` 상태입니다. 어떤 수치도 추정하지 않았습니다.**

---

## 9-2. ✅ 좋은 소식 — GSC는 이미 연결되어 있습니다

`[소스]` `app/layout.tsx:73-75`

```ts
verification: {
  google: 'j32wzFaswXxA6-7Fh5R-J8V2o7xQ4b-eb0-u37ywSYg',
},
```

`[실측]` 라이브 홈페이지 HTML에서도 해당 메타태그가 확인됩니다.

**즉 사이트는 이미 Google Search Console에 소유 확인되어 있으며, 데이터는 축적되고 있습니다.** 소유자가 GSC에 로그인하면 아래 모든 항목을 **즉시** 확보할 수 있습니다. 별도 설정이나 대기 기간이 필요 없습니다.

¹ **단, 구조상 카니발라이제이션은 현재 거의 불가능합니다.** 색인 가능한 실질 페이지가 홈페이지 1개뿐이기 때문입니다([01-url-inventory.md](01-url-inventory.md) 참조). 예외적으로 확인할 가치가 있는 조합은 다음 3가지입니다.

- `/` vs `/faq` — FAQ 6개가 완전 중복 (다만 `/faq`는 canonical이 홈이라 색인 제외 가능성 높음)
- `/` vs `/login` — 동일한 title·description
- `/` vs `/email-preview` — 동일한 title·description

## 9-4. 🔴 GSC에서 **반드시 먼저 확인해야 할 것** — 색인 범위 보고서

실적 데이터보다 우선순위가 높습니다. 이 보고서의 핵심 발견들을 GSC가 확인해 줄 것입니다.

**GSC → 색인 생성 → 페이지** 에서 다음 항목의 URL 수를 확인하세요.

| GSC 상태                                   | 예상되는 URL                                                          | 이 보고서의 근거                                  |
| ------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------- |
| **"페이지에 리디렉션이 있음"**             | `/products`, `/products/category/{plan,pbn,seo,content}` — **5개**    | 사이트맵 URL 6개 중 5개가 307 → `/login` `[실측]` |
| **"대체 페이지(적절한 표준 태그 있음)"**   | `/services`, `/pricing`, `/faq`, `/cases`, `/login`, `/email-preview` | 전 페이지 canonical이 홈 지정 `[실측]`            |
| **"크롤링됨 - 현재 색인이 생성되지 않음"** | 위 페이지들 일부                                                      |                                                   |
| **색인 생성됨**                            | `/` **1개**(예상)                                                     |                                                   |

**GSC → 사이트맵** 에서 `sitemap.xml`의 "발견된 페이지" 대비 "색인 생성됨" 수치를 확인하세요. **6개 제출 → 1개 색인**이 예상됩니다.

> 이 두 화면만 확인하면 본 보고서의 Critical 항목 4건이 **한 화면에서 전부 검증**됩니다.

## 9-6. 리뉴얼 전 GSC 데이터를 반드시 백업해야 하는 이유

**리뉴얼로 URL이 바뀌면 그 이전 데이터는 쿼리-URL 매핑이 끊깁니다.** 리뉴얼 착수 전에 다음을 CSV로 내보내 보관할 것을 권장합니다.

| 백업 항목                                               | 용도                                                                  |
| ------------------------------------------------------- | --------------------------------------------------------------------- |
| 최근 16개월 전체 쿼리 (Clicks·Impressions·CTR·Position) | 리뉴얼 전후 성과 비교 기준선                                          |
| 최근 16개월 페이지별 데이터                             | **어떤 URL이 실제 트래픽을 갖고 있었는지** → 리다이렉트 우선순위 결정 |
| 쿼리+페이지 조합                                        | 페이지별 타깃 키워드 실증                                             |
| 색인 범위 보고서                                        | 리뉴얼 후 개선 검증                                                   |

이 백업은 [11-migration-plan.md](11-migration-plan.md)의 리다이렉트 계획을 **추정이 아닌 실데이터 기반**으로 확정하는 데 필요합니다.

> 현재 리다이렉트 계획은 소스코드와 실측 크롤링에 근거해 작성했으며, GSC 데이터가 확보되면 **트래픽 실적이 있는 URL을 추가로 발견**할 수 있습니다.
