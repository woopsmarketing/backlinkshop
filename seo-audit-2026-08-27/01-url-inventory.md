# A. 전체 URL 인벤토리

**조사일: 2026-08-27** · 출처: `[실측]` curl + Googlebot UA, `[소스]` 리포지토리 커밋 `f773f8d`

크롤링 방법: 리포지토리 `app/` 디렉토리에서 라우트를 전수 추출한 뒤, 각 URL에 Googlebot User-Agent로 HTTP 요청을 보내 상태코드·리다이렉트·HTML 원문을 받아 파싱했습니다. 홈페이지 내부 링크도 따라가 추가 URL을 확인했습니다.

## A-3. 로그인 리다이렉트 URL (10개) — 🔴 SEO 치명

`[소스]` `middleware.ts:88` — `protectedPaths = ['/dashboard', '/credits', '/products', '/orders', '/admin']`

`/products`가 보호 경로에 포함되어 있어 **모든 상품 관련 URL이 비로그인 사용자(= Googlebot)에게 307 리다이렉트**됩니다.

| URL                           | 상태코드 | 최종 URL | 사이트맵 등록   | 홈 링크 |
| ----------------------------- | -------- | -------- | --------------- | ------- |
| `/products`                   | **307**  | `/login` | ✅ priority 0.9 | ✅      |
| `/products/category/plan`     | **307**  | `/login` | ✅ priority 0.8 | ✅      |
| `/products/category/pbn`      | **307**  | `/login` | ✅ priority 0.8 | ✅      |
| `/products/category/seo`      | **307**  | `/login` | ✅ priority 0.8 | ✅      |
| `/products/category/content`  | **307**  | `/login` | ✅ priority 0.7 | ✅      |
| `/products/category/{임의값}` | **307**  | `/login` | —               | —       |
| `/products/[id]` (상품 상세)  | **307**  | `/login` | ❌              | ❌      |
| `/dashboard`                  | 307      | `/login` | ❌              | ❌      |
| `/credits`                    | 307      | `/login` | ❌              | ❌      |
| `/orders`                     | 307      | `/login` | ❌              | ❌      |
| `/admin`                      | 307      | `/login` | ❌              | ❌      |

> ⚠️ `/products/category/bogus` 같은 **존재하지 않는 카테고리도 404가 아닌 307**을 반환합니다. 미들웨어가 라우트 핸들러보다 먼저 실행되기 때문입니다. 무한 URL 공간이 전부 `/login`으로 리다이렉트되는 구조 — 크롤 예산 낭비 요인.

**SEO 영향**: 사이트맵이 Google에게 "이 5개 URL을 색인하라"고 제출하는데, 실제로 크롤링하면 전부 로그인 페이지로 리다이렉트됩니다. Google Search Console에서 **"페이지에 리디렉션이 있음"** 오류로 처리되며, 사이트맵 신뢰도가 하락합니다. 상품 카테고리 페이지는 `PBN 백링크`, `플랜 백링크` 등 상업 키워드를 타깃할 수 있는 자산인데 **콘텐츠가 검색엔진에 단 한 글자도 노출되지 않습니다.**

## A-8. Footer 정책 링크 — 🔴 전부 죽은 링크

`[소스]` `app/page.tsx:1144-1156`

| Footer 표기      | 실제 `href` | 상태           |
| ---------------- | ----------- | -------------- |
| 이용약관         | `href="#"`  | 🔴 페이지 없음 |
| 개인정보처리방침 | `href="#"`  | 🔴 페이지 없음 |
| 환불 정책        | `href="#"`  | 🔴 페이지 없음 |

프롬프트에서 "Footer의 이용약관 / 개인정보처리방침 / 환불정책"을 반드시 확인하라고 지정했으므로 명확히 기록합니다: **세 페이지 모두 존재하지 않으며, Footer 링크는 `#`(현재 페이지 앵커)로 연결되어 아무 동작도 하지 않습니다.**

영향 범위는 SEO를 넘어섭니다.

1. **E-E-A-T 신뢰 신호 부재** — Google은 상거래 사이트의 정책 페이지를 신뢰도 평가 요소로 봅니다. 경쟁사 `linkauthority.kr`은 `/terms`, `/privacy`를 사이트맵에 등록해 두었습니다(07번 문서 참조).
2. **전자상거래법 표시의무** — 국내에서 유료 서비스를 판매하면서 이용약관·개인정보처리방침·사업자 정보(상호, 사업자등록번호, 통신판매업 신고번호, 대표자, 주소, 연락처)를 게시하지 않는 것은 법적 리스크입니다. `[소스]` 전체 코드베이스에서 `사업자등록`·`통신판매업` 문자열이 **0건** 검색되었습니다.
3. **Google Ads 정책** — 결제가 발생하는 서비스는 환불/개인정보 정책 게시가 요구됩니다. 광고 계정 리스크.
